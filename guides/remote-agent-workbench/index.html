Windows 筆電 → Linux 伺服器

遠端 Agent 工作台

Claude Code、Codex 這類 agent 都跑在遠端 Linux 伺服器（例如 cloud6）上，筆電關機也不會停。筆電只負責三件事：連線、管理 agent、看 git 狀態。管理 agent 有兩套工具可選：瀏覽器介面的 agent-deck，或終端機介面的 herdr，兩者可以並存。

agent-deck管 agent（瀏覽器）：開新的 agent、看每個 agent 在跑、在等你、還是出錯，並在網頁裡直接操作。
herdr管 agent（終端機）：agent 專用的多工器，側欄自動顯示狀態，agent 之間還能互相傳訊息、分工。
Windows Terminal用 SSH 連到遠端 Linux 伺服器：deck 分頁（兼網頁隧道）、herdr 分頁、一般 shell 分頁。
VS Code + GitLens用 Remote-SSH 開伺服器上的 repo，只顯示你選的 repo，用 GitLens 看分支、提交與變更。

LINUX 伺服器

tmux session deckagent-deck 網頁伺服器（headless），只綁 127.0.0.1:<PORT>，要 token
tmux session agentdeck_*每個 agent 一個（claude / codex / shell…），由 agent-deck 建立
agent-deck TUI開 deck 分頁時在 SSH 連線裡執行，關掉分頁就結束，不影響上面兩者
herdr 伺服器（背景常駐）工作區／分頁／pane，每個 pane 是真的終端機，裡面跑 claude、codex；斷線不影響
你原本的 tmux session完全不受影響

幾個關鍵觀念

  • agent 一律從 agent-deck 開，才會出現在監控畫面。自己在 tmux 手動開的 claude 不會被追蹤。
  • 斷線不影響工作：網頁伺服器和所有 agent 都在伺服器的 tmux 裡。關掉 Windows Terminal、筆電關機，agent 都會繼續跑。
  • 網頁要靠隧道才看得到：網頁只綁伺服器的 127.0.0.1，筆電要開著「deck」分頁（或任何帶隧道的 SSH 連線），瀏覽器才連得到。
  • 為什麼要 token：伺服器若是多人共用，其他帳號在伺服器上也連得到 127.0.0.1。這個網頁能以你的身分執行任何指令，所以要 token 擋住。token 只需在瀏覽器輸入一次，之後 cookie 會記住。
  • 不建議開到 0.0.0.0：HTTP 明碼傳 token、整個內網都碰得到，而且瀏覽器只在 https 或 localhost 允許推播通知。
以下用尖括號表示每個人不同的值。最快的方法是到「一鍵設定 Prompt」分頁填好值，把 prompt 交給 Claude Code 自動做完；這裡是手動步驟，也方便你看懂 agent 做了什麼。
代號意思範例
<HOST>伺服器 IP 或主機名稱10.x.x.x
<USER> / <SSH_PORT>SSH 帳號與 portalice / 22
<KEY>筆電上的私鑰路徑C:\Users\alice\.ssh\id_ed25519
<ALIAS>SSH 別名，也是 Windows Terminal 分頁名稱cloud6、devbox
<PORT>agent-deck 網頁 port（兩端相同）12021（預設 8420）
<REPO_ROOT>伺服器上放 repo 的資料夾（絕對路徑）/home/alice/repository
00前置需求兩端
  • 筆電：Windows 10/11、Windows Terminal、內建 OpenSSH client（ssh -V）、VS Code 加上擴充套件 Remote - SSH 與 GitLens。
  • 伺服器：Linux、tmux 3.3 以上、curl、jq；claude 與（可選）codex 已安裝並登入。
  • 能用金鑰從筆電 SSH 登入伺服器。第一次連線的 host key 確認要自己手動做一次。
需要 sudo 的安裝（例如 tmux、jq）請自己決定。agent-deck 本身裝在 ~/.local/bin，不需要 sudo。
01筆電 SSH 設定筆電 ~/.ssh/config

先備份 %USERPROFILE%\.ssh\config，再加入兩個別名。<ALIAS>-deck 多一行隧道，只給 deck 分頁用，避免多個連線搶同一個 port。

# >>> agent-workflow >>>
Host <ALIAS>
    HostName <HOST>
    User <USER>
    Port <SSH_PORT>
    IdentityFile <KEY>
    ServerAliveInterval 30
    ServerAliveCountMax 4

Host <ALIAS>-deck
    HostName <HOST>
    User <USER>
    Port <SSH_PORT>
    IdentityFile <KEY>
    ServerAliveInterval 30
    ServerAliveCountMax 4
    LocalForward <PORT> 127.0.0.1:<PORT>
# <<< agent-workflow <<<

驗證：ssh <ALIAS> echo ok 印出 ok。

02伺服器 PATH 與 tmux 設定伺服器

PATH：如果 claude／codex 只寫在 .bashrc（例如裝在 ~/.npm-global/bin 或 nvm 下），登入 shell 會找不到，agent-deck 也就開不起 agent。先確認：

bash -lc 'command -v claude codex agent-deck'

找不到的話，備份 ~/.profile 後在檔尾加上（目錄換成 command -v claude 在互動 shell 裡的實際位置）：

# >>> agent-workflow >>>
case ":$PATH:" in *":<CLAUDE_BIN_DIR>:"*) ;; *) PATH="<CLAUDE_BIN_DIR>:$PATH" ;; esac
case ":$PATH:" in *":$HOME/.local/bin:"*) ;; *) PATH="$HOME/.local/bin:$PATH" ;; esac
export PATH
# <<< agent-workflow <<<

tmux：備份 ~/.tmux.conf（若有），在檔尾加上，然後 tmux source-file ~/.tmux.conf（不會中斷既有 session）。這讓 Claude Code 在 tmux 裡的 Shift+Enter、通知與滑鼠捲動正常。

# >>> agent-workflow >>>
set -g mouse on
set -g allow-passthrough on
set -s extended-keys on
set -as terminal-features 'xterm*:extkeys'
# <<< agent-workflow <<<
開了 mouse on 之後，在 Windows Terminal 要按住 Shift 再拖曳才能選取複製文字。
03安裝 agent-deck 與狀態 hooks伺服器

先下載安裝腳本看過，再執行。--skip-tmux-config 讓它不要改你的 tmux 設定。

curl -fsSL https://raw.githubusercontent.com/asheshgoplani/agent-deck/main/install.sh -o /tmp/agent-deck-install.sh
less /tmp/agent-deck-install.sh      # 看過內容
bash /tmp/agent-deck-install.sh --non-interactive --skip-tmux-config
bash -lc 'agent-deck version'

安裝狀態偵測 hooks（狀態燈準不準靠這一步）。會修改 Claude 與 Codex 設定，先備份 ~/.claude/settings.json 與 ~/.codex/config.toml：

bash -lc 'agent-deck hooks install && agent-deck hooks status'
bash -lc 'agent-deck codex-hooks install && agent-deck codex-hooks status'

建立網頁 token（權限 600，只有自己讀得到）：

install -d -m 700 ~/.config/agent-deck
install -m 600 /dev/null ~/.config/agent-deck/web-token
head -c 32 /dev/urandom | od -An -tx1 | tr -d ' \n' > ~/.config/agent-deck/web-token
04啟動腳本 deck-up伺服器 ~/.local/bin/deck-up

新版 agent-deck 的 TUI 拒絕在 tmux 裡執行，所以把兩者拆開：網頁伺服器用 --no-tui 常駐在 tmux session「deck」，TUI 則直接在你的 SSH 分頁裡跑。-e PATH=… 把登入 shell 的 PATH 帶進 tmux，agent-deck 才找得到 claude／codex。

#!/usr/bin/env bash
# 確保 agent-deck 網頁伺服器常駐在 tmux session「deck」（headless，只綁 127.0.0.1:<PORT>），
# 然後在目前終端機開 agent-deck TUI。TUI 不能在 tmux 裡跑，所以網頁和 TUI 分開。
if ! tmux has-session -t deck 2>/dev/null; then
  tmux new-session -d -s deck -e "PATH=$PATH" \
    "$HOME/.local/bin/agent-deck web --no-tui --push --listen 127.0.0.1:<PORT> --token-file $HOME/.config/agent-deck/web-token"
  sleep 1
fi
tmux has-session -t deck 2>/dev/null && echo "agent-deck web: running (tmux session deck, 127.0.0.1:<PORT>)"
[ -n "$TMUX" ] && exit 0
"$HOME/.local/bin/agent-deck"
exec bash -l

chmod 755 ~/.local/bin/deck-up。離開 TUI 後會停在伺服器 shell，分頁不會被關掉，隧道也還在。

05Windows Terminal 分頁筆電 settings.json

Windows Terminal 按 Ctrl+, → 左下「開啟 JSON 檔案」。先備份，再在 profiles.list 加入兩筆，GUID 用 PowerShell 的 [guid]::NewGuid() 產生。不用改 defaultProfile。

{
    "guid": "{<新 GUID 1>}",
    "name": "<ALIAS> · deck",
    "commandline": "ssh -t <ALIAS>-deck \"bash -lc ~/.local/bin/deck-up\"",
    "bellStyle": ["window", "taskbar"],
    "tabTitle": "deck",
    "suppressApplicationTitle": true
},
{
    "guid": "{<新 GUID 2>}",
    "name": "<ALIAS> · shell",
    "commandline": "ssh <ALIAS>",
    "bellStyle": ["window", "taskbar"]
}

Windows Terminal 不懂 SSH，它只是執行 ssh <別名>；連線資訊都來自 ~/.ssh/config。以後 IP 換了只改那裡。

06第一次開網頁筆電
  1. Windows Terminal → + 旁的 ⌄ → 選「<ALIAS> · deck」。應看到 agent-deck TUI（第一次可能詢問是否傳送匿名使用資料，自己決定）。
  2. 取得 token：在另一個分頁執行 ssh <ALIAS> cat ~/.config/agent-deck/web-token。不要把 token 存進會同步或分享的檔案。
  3. 瀏覽器開 http://localhost:<PORT>/?token=<token>，之後 cookie 會記住，直接開 http://localhost:<PORT> 即可。
  4. 右上角齒輪（Tweaks）→ 開啟 Notifications，agent 等你回應時瀏覽器會跳通知。
07VS Code + GitLens筆電＋伺服器

使用者設定（%APPDATA%\Code\User\settings.json，先備份）加入兩項：指定伺服器平台，連線時不再詢問；並讓 VS Code 不要自動轉送 agent-deck 的 port，避免和 deck 分頁搶。

"remote.SSH.remotePlatform": { "<ALIAS>": "linux" },
"remote.portsAttributes": {
    "<PORT>": { "label": "agent-deck (use <ALIAS>-deck tunnel)", "onAutoForward": "ignore" }
}

只顯示想看的 repo：VS Code 的 Git 預設只往下掃一層，放在子資料夾的 repo 不會出現，全部列出又太多。在伺服器建立 workspace 檔 <REPO_ROOT>/<ALIAS>.code-workspace，清單就是要顯示的 repo：

{
  // 要在 VS Code 顯示的 repo：加一行或刪一行即可（路徑相對於這個檔案）
  "folders": [
    { "path": "<repo-a>" },
    { "path": "<子資料夾>/<repo-b>" }
  ],
  "settings": {}
}

開啟方式：

code --file-uri "vscode-remote://ssh-remote+<ALIAS><REPO_ROOT>/<ALIAS>.code-workspace"
  • 之後從 File → Open Recent 一鍵回來。
  • 增減 repo：檔案總管右鍵 Add Folder to Workspace… / Remove Folder from Workspace，或直接改檔。
  • VS Code 一律用 <ALIAS>，不要用 <ALIAS>-deck（會搶 port）。
  • GitLens 會在 Source Control 與左側 GitLens 面板顯示每個 repo 的分支、提交歷史、blame 與 worktree。

herdr（Apache-2.0）是給 AI agent 用的終端機多工器，可以想成「會看懂 agent 狀態的 tmux」。以 herdr 0.9.3 為準。點下面切換說明。

兩種用法：模式 A（建議）在 Windows Terminal 裡 SSH 進伺服器再執行 herdr，筆電不用裝任何東西；模式 B 在 Windows 裝原生 herdr，多了 Windows 系統通知，但執行檔沒有簽章，公司電腦可能被端點防護擋下（實測出現「Access is denied」）。以下是模式 A。也可以到「一鍵設定 Prompt」選 herdr，交給 agent 做完。
01SSH 別名筆電

沿用 agent-deck 設定步驟 01 的 <ALIAS> 即可（herdr 不需要隧道，不要用 <ALIAS>-deck）。沒有的話照那一步建立。驗證 ssh <ALIAS> echo ok。

02在伺服器安裝 herdr伺服器

安裝腳本會下載官方預編譯執行檔、驗證 SHA-256，放到 ~/.local/bin，不需要 sudo。一樣先看過再跑：

curl -fsSL https://herdr.dev/install.sh -o /tmp/herdr-install.sh
less /tmp/herdr-install.sh      # 看過內容
sh /tmp/herdr-install.sh
bash -lc 'herdr --version'      # 登入 shell 要找得到

登入 shell 找不到的話，照 agent-deck 設定步驟 02 把 $HOME/.local/bin 加進 ~/.profile。不要在非互動的 ssh 指令裡直接執行 herdr，它會開互動畫面。

03安裝 Claude／Codex integration伺服器

讓 herdr 準確判斷狀態，並在 herdr 重啟或伺服器重開機後自動接回對話（claude --resume、codex resume）。先備份 ~/.claude/settings.json、~/.codex/config.toml、~/.codex/hooks.json（若有）：

bash -lc 'herdr integration install claude'
bash -lc 'herdr integration install codex'
bash -lc 'herdr integration status'      # claude、codex 應顯示 current

會新增 ~/.claude/hooks/herdr-agent-state.sh 並在 Claude 設定加 hook；Codex 則新增 ~/.codex/herdr-agent-state.sh、hooks.json，並在 config.toml 加上 [features] hooks = true。實測和 agent-deck 的 hooks、statusLine 可以並存，裝完比對備份確認原本設定都在。

04安裝 herdr skill（agent 協作用）伺服器

裝了之後，在 herdr 裡跑的 Claude 會用 herdr CLI 開旁邊的 pane、啟動 Codex、丟任務、等它做完並讀結果。用 herdr 自帶的版本，不需要 Node：

bash -lc 'mkdir -p ~/.claude/skills/herdr && herdr --skill > ~/.claude/skills/herdr/SKILL.md'
05Windows Terminal 分頁筆電 settings.json

備份 settings.json，在 profiles.list 加一筆（GUID 用 [guid]::NewGuid()）：

{
    "guid": "{<新 GUID>}",
    "name": "<ALIAS> · herdr",
    "commandline": "ssh -t <ALIAS> \"bash -lc herdr\"",
    "bellStyle": ["window", "taskbar"],
    "tabTitle": "herdr",
    "suppressApplicationTitle": true

06第一次使用與驗證筆電
  1. 開「<ALIAS> · herdr」，應看到左邊側欄（spaces / agents）、右邊 pane。
  2. 在 pane 執行 cd <測試 repo> && claude，側欄 agents 應出現 claude，狀態會跟著工作變化。
  3. 另一個 pane 執行 codex --no-daemon。第一次會跳出 Hooks 審核對話框（「1 hook needs review」），那是步驟 03 裝的 herdr hook，按 t 信任。
  4. 關掉分頁再重開，應回到同一個畫面，agent 還在。

從筆電確認伺服器狀態：ssh <ALIAS> '~/.local/bin/herdr agent list'。

基本觀念

名詞意思
herdr 伺服器在伺服器背景常駐，所有 pane 和 agent 都在它裡面。關掉 Windows Terminal、筆電關機都不會停
Workspace 工作區一個專案一個工作區，agent 狀態才不會混在一起。側欄上方 spaces 列出，下方顯示目前 git 分支
Tab 分頁 / Pane工作區裡的分頁；分頁可以切成多個 pane，每個 pane 都是真的終端機
側欄 agents自動偵測 pane 裡的 claude、codex 等，依工作區分組顯示狀態
Agent 名字可替 agent 取名（例如 coder、review），之後用名字互相傳訊息。名字跟著 agent 走，agent 結束就清掉
狀態意思
working正在工作
blocked卡在授權或提問畫面，在等你
done做完了、你還沒看過
idle閒置；done 被看過後也變成 idle。herdr 不認得的提問畫面也會退回 idle（已知限制）

滑鼠：點 pane、分頁、工作區、側欄 agent 來切換；拖曳邊框調整大小；右鍵叫出選單（分割、開分頁）；拖曳反白自動複製，雙擊選字；貼上用 Ctrl+Shift+V。

快捷鍵：先按 Ctrl+B 放開，再按下表的鍵。

agent 互相溝通

原理：每個 pane 裡的 agent 都能呼叫 herdr CLI，用「名字」指定對方，送訊息、等它做完、讀它的畫面。實測 Claude 和 Codex 可以雙向互傳。

1. 開兩個有名字的 agent

herdr workspace create --cwd <repo> --label agent-demo --focus     # 回傳 root_pane，例如 w3:p1
herdr pane split w3:p1 --direction right --cwd <repo> --no-focus   # 回傳新 pane，例如 w3:p2
herdr agent start alice --kind claude --pane w3:p1
herdr agent start bob   --kind codex  --pane w3:p2 -- --no-daemon

手動開也可以：Ctrl+B Shift+N 開工作區、Ctrl+B v 分割，各自輸入 claude、codex --no-daemon，再用 herdr agent rename <pane ID> <名字> 取名。名字限小寫英文開頭、可含數字 - _，最長 32 字。

2. 溝通用的指令

指令用途
herdr agent list列出所有 agent 的名字、種類、狀態、pane ID
herdr agent prompt <名字> "訊息" --wait送訊息並等對方做完（idle / done / blocked）
herdr agent read <名字> --source recent-unwrapped --lines 40讀對方畫面上的回覆
herdr agent wait <名字> --until blocked等對方進入特定狀態
herdr agent send-keys <名字> esc對對方按鍵（例如關掉對話框）
herdr agent rename <名字或 pane> <新名字>改名或 --clear 清掉

3. 叫 agent 去做

在 alice（Claude）的輸入框打，一定要提到「herdr」：

用 herdr 跟名叫 bob 的 agent 說 hi，請它回一句話，然後告訴我它回了什麼
沒寫「herdr」的話，Claude 會改用 Claude Code 自己的跨 session 訊息功能，去找你帳號下其他 Claude session（例如 Remote Control session），結果回報「找不到名叫 review 的 session」。herdr skill 刻意設定成「使用者明確提到 Herdr 才用」。

常見組合：「用 herdr 在旁邊開一個 Codex，叫它審查目前的 git diff，等它做完後把重點告訴我」（Claude 寫、Codex 審）。

注意事項（實測踩過的）

  • 不要在 herdr 的 pane 裡再開 tmux，agent 狀態偵測會失效。
  • Codex 用 codex --no-daemon 啟動，共用 daemon 可能把狀態回報到錯的 pane。
  • Codex 第一次啟動跳 Hooks 審核：按 t 信任 herdr 的 hook；只按 esc 下次還會跳。
  • Codex 的沙盒會擋 herdr CLI：每條 herdr agent … 都會問要不要在沙盒外執行，狀態顯示 blocked。選 y 只允許這次；常用的話選 p（以後 herdr agent 開頭的指令不再問），代價是 Codex 之後可以不經詢問指揮其他 agent。
  • 讀 blocked 的 agent 要用 --source visible，讀很多行會失敗。
  • Claude 輸入框的灰字是建議輸入，不是有人打的，按 Enter 不會送出。
  • herdr server stop、herdr update 可能結束所有 pane 裡的程式，先讓 agent 停在可以中斷的地方。
  • 伺服器重開機：herdr 不會自動啟動；開「<ALIAS> · herdr」就會啟動並還原工作區、接回 Claude／Codex 對話，但重開機前正在跑的指令會中斷。

一句話選擇

  • 想在瀏覽器一眼看完所有 agent、收推播、看花費 → agent-deck。
  • 習慣在終端機工作、想讓 agent 互相分工（Claude 寫、Codex 審） → herdr。
  • 兩者可以同時裝在同一台伺服器，hooks 互不衝突；但同一個 agent 只會被開啟它的那套工具追蹤。

agent-deck 優點

  • 瀏覽器介面，不熟終端機也好上手
  • 手機、平板也能看（有隧道即可）
  • 花費、用量、Command Center 總覽
  • Fork、MCP、Skills 管理

agent-deck 缺點

  • 設定步驟多：token、隧道、port、deck-up
  • TUI 不能放在 tmux 裡，要特別處理
  • 網頁版部分功能（MCP、Conductor）還沒做

herdr 優點

  • 安裝簡單，不用開 port、不用 token
  • 同一畫面分割多個 agent，滑鼠就能操作
  • agent 互相溝通、分工最直接
  • 重開機後自動接回對話

herdr 缺點

  • 只有終端機介面，沒有網頁
  • 沒有花費統計
  • 模式 A 沒有系統通知
  • Codex 每條 herdr 指令都要批准（可設定不再問）

用 agent-deck 的一天

  1. Windows Terminal 開「<ALIAS> · deck」，整天開著（它負責隧道）。
  2. 瀏覽器開 http://localhost:<PORT>，看所有 agent 狀態。
  3. 要開新 agent：右上 + New → 填名稱、工作目錄、工具 → Create session。
  4. 要看 code / git：VS Code → File → Open Recent → 你的 workspace。
  5. 要跑其他指令：開「<ALIAS> · shell」，開幾個都可以。

什麼會停、什麼不會

情況agent 與網頁伺服器要做什麼
關掉 deck 分頁 / 筆電關機繼續跑重開 deck 分頁，網頁重新整理
網路斷線繼續跑同上
伺服器重開機全部停止開 deck 分頁，deck-up 會自動重啟網頁伺服器；agent 要在網頁重新開

隨時可用 ssh <ALIAS> "tmux ls" 確認，有 deck 就是網頁伺服器還活著。

用 herdr 的一天

  1. 開「<ALIAS> · herdr」。
  2. 每個 repo 一個工作區（Ctrl+B Shift+N），在 pane 裡跑 claude 或 codex --no-daemon。
  3. 看側欄狀態；Ctrl+B g 再按 b 找出所有 blocked 的 agent，Enter 跳過去處理。
  4. 下班直接關分頁或 Ctrl+B q，agent 繼續跑；明天再開就接回。

只要網頁、不要 TUI

網頁伺服器已在跑時，可以只開隧道：

ssh -N <ALIAS>-deck

第一次啟動或伺服器重開機後，還是要開一次 deck 分頁讓 deck-up 把網頁伺服器帶起來。

UP更新 agent-deck伺服器 
bash -lc 'agent-deck update --check'   # 只檢查有沒有新版
bash -lc 'agent-deck update'           # 下載並安裝最新版
bash -lc 'agent-deck update --version 1.16.26'   # 指定版本（也可降版）

更新後，重啟網頁伺服器讓新版生效。只會重啟網頁，agent 不受影響：

tmux kill-session -t deck
# 然後在 Windows Terminal 重開「<ALIAS> · deck」，deck-up 會用新版啟動

確認 hooks 還在（有時新版需要重新安裝）：

bash -lc 'agent-deck hooks status; agent-deck codex-hooks status'
bash -lc 'agent-deck hooks install; agent-deck codex-hooks install'   # 若顯示需要升級

想要每天自動更新：agent-deck update --install-timer（systemd user timer），用 --uninstall-timer 移除。

RM移除 agent-deck（伺服器）伺服器
  1. 停掉網頁伺服器，並在網頁上先 Stop / Delete 不要的 agent：tmux kill-session -t deck
  2. 移除 hooks： 
    bash -lc 'agent-deck hooks uninstall; agent-deck codex-hooks uninstall'
  3. 先預覽，再移除程式： 
    agent-deck uninstall --dry-run       # 列出會刪什麼
agent-deck uninstall --keep-data     # 只刪程式，保留 session 資料
agent-deck uninstall                 # 連設定、資料、快取、token 一起刪
  4. 刪除啟動腳本：rm ~/.local/bin/deck-up
  5. 從 ~/.tmux.conf、~/.profile 刪掉 # >>> agent-workflow >>> 標記區塊，或用 *.bak-日期 備份還原。
RM移除筆電端設定筆電
  • ~/.ssh/config：刪掉 agent-workflow 標記區塊（兩個別名）。
  • Windows Terminal：設定 → 刪除「<ALIAS> · deck」「<ALIAS> · shell」兩個設定檔，或還原 settings.json.bak-日期。
  • VS Code：從使用者設定移除 remote.SSH.remotePlatform 與 remote.portsAttributes 裡的這兩項；需要的話刪掉伺服器上的 .code-workspace。
  • 瀏覽器：清除 localhost:<PORT> 的 cookie 與通知權限。
UP更新 herdr伺服器

先讓 agent 停在可以中斷的地方：少數版本升級需要重啟 herdr 伺服器，會結束 pane 裡的程式。

bash -lc 'herdr status'      # 看 client / server 版本
bash -lc 'herdr update'      # 下載並安裝最新版（stable 頻道）
bash -lc 'herdr integration status'   # 確認 integration 仍是 current

有裝 Windows 原生版的話，兩邊要各自更新。

RM移除 herdr兩端
  1. 確認沒有要保留的 agent 後停止伺服器（會結束所有 herdr pane）：herdr server stop
  2. 移除 integration： 
    bash -lc 'herdr integration uninstall claude; herdr integration uninstall codex'
    Codex 的 config.toml 不會自動還原，從備份還原或刪掉 [features] hooks = true。
  3. 刪除執行檔與 skill：rm "$(bash -lc 'command -v herdr')" ; rm -r ~/.claude/skills/herdr
  4. 需要的話刪掉設定與工作階段狀態：rm -r ~/.config/herdr
  5. 筆電：刪除 Windows Terminal 的「<ALIAS> · herdr」設定檔。有裝原生版的話刪除 %USERPROFILE%\.herdr、%APPDATA%\herdr，並移除 PATH 裡的 herdr 路徑。
deck 分頁一開就閃退

多半是 agent-deck TUI 被包在 tmux 裡執行（新版會拒絕：「The agent-deck TUI is designed to run OUTSIDE of tmux」）。用設定步驟 04 的 deck-up：網頁伺服器 --no-tui 放 tmux，TUI 在外面跑。

查原因：ssh <ALIAS> "tmux capture-pane -p -t deck"。

瀏覽器顯示 ERR_CONNECTION_REFUSED

筆電沒有隧道。確認「<ALIAS> · deck」分頁有開著（不是 shell 分頁）。伺服器端可用 ssh <ALIAS> "curl -s -o /dev/null -w %{http_code} http://127.0.0.1:<PORT>/" 確認網頁伺服器有回 200。

開 claude 顯示 error / tmux session is not available

agent-deck 的 PATH 裡找不到 claude。查 log：

tail ~/.local/share/agent-deck/logs/session-id-lifecycle.jsonl   # 找 "tool not found on PATH"

修正：照步驟 02 把 claude 的目錄加進 ~/.profile，確認 deck-up 有 -e "PATH=$PATH"，然後 tmux kill-session -t deck 再重開 deck 分頁，最後在網頁按 Restart session。

不要用非登入的 ssh 指令直接啟動網頁伺服器（例如 ssh host 'tmux new -d …'），那樣 PATH 不會讀 ~/.profile。一律透過 bash -lc deck-up。
bind: Address already in use

同時開了兩個帶隧道的連線（兩個 deck 分頁，或 VS Code 用了 -deck 別名）。關掉多的那個；VS Code 一律用不帶 -deck 的別名。

網頁回 401 / 要求登入

cookie 過期或換了瀏覽器。重新用 ?token=… 開一次。token 外洩的話重新產生（步驟 03 最後三行），再 tmux kill-session -t deck 並重開 deck 分頁。

沒有推播通知

出現「Notifications are blocked for this site」代表瀏覽器擋了這個網站的通知（多半是之前跳詢問時按了封鎖，或瀏覽器預設不讓網站詢問）。依序檢查：

  1. 點網址列最左邊的圖示 →「網站權限／網站設定」→ 通知 改成「允許」，重新整理頁面。
  2. 仍不行：Edge 到 edge://settings/content/notifications、Chrome 到 chrome://settings/content/notifications，確認沒有把 localhost:<PORT> 放在「封鎖」，且沒有關閉「網站可以要求傳送通知」。
  3. 回到 agent-deck → Tweaks → 打開 NOTIFICATIONS。
  4. Windows「設定 → 系統 → 通知」要允許瀏覽器；「專注」或「勿擾」開著時也不會跳。

必須用 http://localhost:<PORT> 開，用 IP 開的話瀏覽器根本不允許推播。

VS Code 只看到部分 repo

Git 預設只掃 workspace 根目錄下一層。用 .code-workspace 把要看的 repo（含子資料夾裡的）各自列成一個 folder，見步驟 07。

herdr：叫 Claude 傳訊息給另一個 agent，卻說找不到 session

prompt 裡沒有提到「herdr」，Claude 改用自己的跨 session 訊息功能去找你帳號下的其他 Claude session。改成「用 herdr 跟名叫 xxx 的 agent 說…」，或直接寫出 herdr agent prompt xxx "…" --wait。

herdr：Codex 一直停在 blocked

兩種常見原因：(1) 第一次啟動的 Hooks 審核對話框，按 t 信任；(2) Codex 沙盒擋 herdr CLI，在詢問畫面選 y（這次）或 p（以後不問）。查看畫面：herdr agent read <名字> --source visible。

herdr：Windows 原生版安裝出現 Access is denied

Windows 拒絕執行未簽章的 herdr.exe，多半是公司端點防護、AppLocker 或 SmartScreen。這是安全政策，不要繞過；改用模式 A，或請 IT 加入允許清單。殘留的 %USERPROFILE%\.herdr 可以自行刪除。

在 PowerShell 下的 ssh 指令引號被吃掉

Windows PowerShell 5.1 傳參數給 ssh.exe 時會丟掉內層雙引號，像 ssh host 'bash -lc "…"' 會變形。改用 Git Bash，或把遠端指令寫成腳本用 ssh host 'bash -s' < script.sh 送過去。

交給 agent 一次做完

在 Windows 筆電上開 Claude Code（desktop app 或終端機皆可），選要裝哪一套、填好下面的值，複製 prompt 貼給它。沒填的欄位會保留成 <代號>，agent 會先問你。值只存在你的瀏覽器，不會上傳。

這份會用到全部欄位。
